# LiDAR_Damage_assessment

Multi-tier floor plans: **RoomPlan LiDAR**, **Stray Scanner** depth, and **video v0** → stitch, QA gates, intervals.  
Phases 1–3 run **offline** (no API keys). Azure is for **Phase 4+** only — see [docs/AZURE_WHEN_NEEDED.md](docs/AZURE_WHEN_NEEDED.md).

Brief: [docs/ASSESSMENT_BRIEF.md](docs/ASSESSMENT_BRIEF.md) · Phases: [docs/PHASES.md](docs/PHASES.md)

## Setup

```powershell
python -m venv .venv
.\.venv\Scripts\activate
pip install -e ".[dev]"
```

Optional Azure (after `az login`):

```powershell
python scripts/_write_env_from_consolidated.py
```

## Capture data

Real scans live under **`data/captures/<capture_id>/`** (not in git). See [data/README.md](data/README.md) and `data/manifest.csv` for downloads.

```powershell
housefloor run --capture data\captures\<your_capture_id>
housefloor run --capture data\captures\<your_capture_id> --tier auto
```

## Scoring (ground truth)

Fill `data/ground_truth/<capture_id>.json` with **measured** values, then:

```powershell
python -m eval.cli score --capture single_room\c00a170fe1 --plan single_room\c00a170fe1\out_stray_v3\plan.json --tier lidar
```

Pipeline never reads GT; calibration multipliers live in `configs/calibration.json`.

Benchmark report for every capture in `data/manifest.csv` that has measured ground truth:

```powershell
python -m eval.run --rerun   # runs the pipeline on each capture, writes docs/BENCHMARK_REPORT.md
```

## Constraints and limitations

**Device.** We have one iPhone 13 Pro and no iPhone 15 or newer. The 13 Pro meets the spec for the LiDAR tier, which asks for a Pro-class device. The photo and video tiers specify iPhone 15 or newer, so our own photos and video are a disclosed deviation. Following the hiring team's guidance for this constraint, the pipeline is developed and demonstrated on the sample data they provided.

**Two kinds of evidence.**
- *Provided sample data* (`single_room`, `single_scan_floor_only`, `single_scan_with_ceiling`; Stray Scanner). No measurements came with these captures, so results on them show that the pipeline runs and is internally consistent, not that it is accurate.
- *Our own room, B1* (bedroom; Stray Scanner LiDAR, iPhone photos at 1× and 0.5×, iPhone video). We measured it with a tape, so this is where accuracy is reported: [docs/BENCHMARK_REPORT.md](docs/BENCHMARK_REPORT.md), generated by `python -m eval.run --rerun`.

**Ground truth.** Tape measure, taken by two people: room length and width, ceiling height (two readings), and the width and height of both doors and both windows. Every assumption is listed in `data/ground_truth/lidar_B1_rep1.json`.

**Benchmark coverage.** Covered: one room captured at all three tiers on one device. Not covered: a multi-room capture with a connector, and a room with staged damage.

**Known limitations of the current pipeline.**
- Video tier: on Stray Scanner captures it reuses the recorded odometry and depth for scale, so video results on those captures are not video-only.
- Photo tier: without the optional Azure model it outputs a wide prior, not a measurement from the photos.
- Calibration multipliers in `configs/calibration.json` were fitted on a synthetic test fixture, not on measured rooms.
- Mirrors, glass, wet-look floors and low light have not been tested on real captures yet.
- Raw captures are not in git (brief rule 7). `data/manifest.csv` lists each one with its sha256; `scripts/fetch_data.py` downloads them once their URLs are filled in.
